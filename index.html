Tick-Level Quantitative Trading and Research Platform

Personal Project

Personal research platform | Data, features, evaluation, orchestration, risk, and execution interfaces

Built a personal tick-level FX/XAUUSD research platform spanning market data, features, model experiments, backtesting, risk allocation, and execution interfaces. Each component has a defined responsibility: research produces evidence, validation evaluates it, and selection and execution consume it through separate interfaces.

Data and evaluation: Lyre feeds Argus feature workflows; Volante produces model artifacts; Nemesis evaluates strategy evidence. Coordination and execution: Aletheia orchestrates stages, Metis allocates risk, and Hermes handles terminal-facing commands and receipts.

Lyre - Tick-Level Market Data Infrastructure

Provides canonical tick/bar data for feature generation and replay, with high-volume columnar reads separated from metadata management.

Python, PyArrow, Parquet, SQLite, tick/bar data, performance testing

  • Storage design: organized market data into canonical shards and partitioned Parquet, with SQLite managing metadata separately from the Arrow read path.
  • Performance validation: built batch-reading, benchmark reporting, and performance-gate tooling for repeatable data-access tests.
  • Downstream contract: provided shared data access for feature generation and backtesting so each consumer does not reimplement ingestion and storage.
  • Benchmark configuration: used 65,536-row Arrow batches and a read-performance gate with a target of 1M+ rows/sec for tick-data research workloads.

Argus - Time-Aware Feature Engineering

Transforms tick/bar inputs into research features while preserving what information was available at each decision time, keeping future observations out of historical inputs.

Python, Polars, Arrow, tick/bar features, no-lookahead evaluation

  • Temporal logic: implemented no-lookahead feature workflows around tick/bar inputs and the timing of information available to downstream decisions.
  • Computation: used Polars/Arrow columnar processing for repeatable feature generation, separating feature computation from strategy and execution logic.

Nemesis - Reproducible Backtesting and Validation

Evaluates strategies under explicit instrument and trading-cost assumptions, with run records and deterministic replay checks for comparing experiments.

Python, strategy protocols, execution-cost models, deterministic replay

  • Simulation contract: implemented MT4-style strategy interfaces with instrument contracts and spread, slippage, commission, and margin models.
  • Evaluation records: captured run metadata, trade ledgers, equity curves, and risk metrics, using deterministic replay checks to compare repeated runs.
  • Validation boundary: evaluates strategy evidence separately from model training and downstream selection or execution decisions.

Aletheia - Research Pipeline Orchestrator

Coordinates multi-repository workflows with dependency-aware execution and recovery, preventing downstream stages from proceeding without the required inputs and evidence.

Python, dependency graphs, subprocess orchestration, audit trails, recovery

  • Scheduling: implemented dependency validation, cycle rejection, parallel execution of independent steps, timeouts, retries, and backoff.
  • Recovery: added atomic state publication, process locks, stale-state recovery, heartbeats, and graceful process-group shutdown for interrupted runs.
  • Evidence gates: gated downstream steps on schema, status, type, and freshness checks, with hash-chained audit records and file fingerprints for provenance and unchanged-input detection.

Metis - Strategy Selection and Risk Reservation

Allocates risk from validated strategy evidence and execution feedback, using durable reservations to keep repeated requests and reconciliation consistent.

Python, SQLite transactions, idempotency, reconciliation, risk budgets

  • Selection rules: reject unvalidated or degraded candidates, incorporate market state and execution feedback, and record reasons for allocations.
  • State consistency: implemented SQLite-backed risk reservations with transactional budget checks, account-bound grants, and idempotent replay to prevent duplicate reservations on repeated requests.
  • Reconciliation: connected persisted reservation state with execution ownership and inventory reconciliation across the risk workflow.

Hermes - MT4 Execution Gateway

Python, HTTP APIs, authentication, command lifecycle, MT4 integration

  • Command lifecycle: implemented command identifiers, locking, atomic publication, expiry, and receipt reconciliation to make submission and recovery behavior explicit.
  • Validation: added health, authentication, recovery, and integration tests, with real-terminal acceptance tracked separately from software validation.
